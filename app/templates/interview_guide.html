Top 10 Technical Interview Questions & Model Answers

Master these core concepts before your interview tomorrow

1 What is Deluge, and how does it differ from languages like Python or JavaScript?

Deluge (Data Enriched Language for the Universal Grid Environment) is Zoho's proprietary low-code scripting language running on Zoho's cloud grid. Unlike general-purpose languages, Deluge has native built-in integration tasks for the entire Zoho ecosystem (e.g. zoho.crm.*, zoho.books.*, zoho.desk.*). It abstracts away complex HTTP wrappers, connection boilerplate, and JSON parsing into simple Map and List operations.

2 Explain the Zoho OAuth 2.0 authentication lifecycle.

Zoho uses standard OAuth 2.0. The developer registers a Client in the Zoho Developer Console (Client ID & Client Secret) and generates an initial Grant Code. This Grant Code is exchanged at https://accounts.zoho.com/oauth/v2/token for a Refresh Token (permanent unless revoked) and an Access Token (valid for 1 hour). All API requests pass Authorization: Zoho-oauthtoken {access_token}. Production apps must maintain a background token manager that refreshes the access token before expiry.

3 How do you handle Zoho API Rate Limits and Concurrency Limits?

Zoho enforces two types of limits: Daily Credit Limits (e.g., 25,000 to 100,000+ API credits/day based on edition) and Concurrency Limits (e.g., maximum 10-25 concurrent requests). In my architecture: 1) Check response headers X-Rate-Limit-Remaining to throttle before hitting limit; 2) Batch API calls where possible using bulk APIs (up to 100 records per POST/PUT); 3) Implement exponential backoff and retry queues for HTTP 429 (Too Many Requests).

4 What is the difference between a Workflow Rule, a Blueprint, and a Scheduled Function?

• Workflow Rules: Triggered passively by database events (record creation, field edit, deletion, or date-based). Ideal for immediate automation like scoring and email alerts.
• Blueprints: Process compliance state machines that enforce stage-by-stage transitions with required fields and checklists before progressing (e.g. mandatory NDA before sending Proposal).
• Scheduled Functions: Cron-like batch jobs executed at specified intervals (hourly, daily, weekly) for nightly data maintenance, license audits, or batch sync.

5 What is COQL (Common Object Query Language) in Zoho CRM?

COQL allows querying Zoho CRM records using SQL-like syntax (SELECT Last_Name, Email, Annual_Revenue FROM Leads WHERE Annual_Revenue > 100000 LIMIT 50) via the /crm/v2/coql endpoint. It is significantly faster and more expressive than traditional criteria filters for complex multi-field conditions and joins across related modules.

6 How do you securely send external Webhooks using Deluge?

Use the Deluge invokeurl task specifying the target URL, HTTP method (POST), JSON headers, and payload string. To ensure integrity and authenticity, generate an HMAC-SHA256 signature of the payload using a shared secret (zoho.encryption.hmacSha256(...)) and send it in an X-Zoho-Signature header. The receiving server validates the hash before processing.

7 Explain the standard B2B entity relationship in Zoho CRM.

• Lead: An unvetted person or inquiry (e.g. form submission).
• Account: The organization / company entity (1 Account : Many Contacts, 1 Account : Many Deals).
• Contact: An individual person associated with an Account.
• Deal (Opportunity): The revenue transaction with stages, closing date, and expected amount.
Conversion splits a qualified Lead into an Account, a Contact, and an optional Deal.

8 How does Deluge error handling and debugging work?

Deluge provides try { ... } catch (e) { ... } blocks for runtime exception trapping. The info "message" statement outputs to the function execution log or Workflow Audit Log in Zoho CRM Setup. Developers inspect these logs to verify variable states, HTTP response codes, and task return maps.
